Pins: clean PyBench `0ef3c56f9d300e7813ac5a555e6d2ac7cb64a57e`; no R protocol/source change is needed for this option. This is a candidate for Sable/Forge design review, not an implementation authorization or a substitute for the stopped disk-backed stage-1 plan.

`src/pybench/protocol_v3.py:_snapshot()` (lines 695-703) builds `dict[relative_path, bytes]`; ordinary v3 `execute_operation_pack_v3()` stores `before = _snapshot(root)` at line 1447 and `after = _snapshot(root)` at line 1555. Ordinary v4 repeats that at `src/pybench/protocol_v4.py:3302-3305,3532-3536`. Only the changed-path computation uses the post-handler byte map; rollback uses the original `before` map (`protocol_v3.py:_restore()`, v4 exception path). Independent output semantic validation, declared output hashes, `_tree` path inventory, receipts and R-side audit are separate checks.

The smallest option with **no new backup owner** is to retain the exact in-memory `before` bytes for rollback, but walk/read every post-handler staged file in bounded blocks and compare it byte-for-byte to the corresponding `before` value without storing a second full byte map. Read even new files to EOF as the current after-snapshot does; mark new/deleted/replaced files changed, preserve symlink/special-object and error behavior, and retain the independent `_tree` inventory. Use exact byte comparison, not a writer claim, size/mtime or a new hash-equivalence assumption. Keep all output semantic/canonical checks, mutation manifest, and R independent audit. The existing R abort may still discard the stage after child death; recoverable Python exceptions continue using the unchanged in-memory `before` rollback. No new path, wire grant, or disk backup is introduced.

If `S0` and `S1` are pre/post staged bytes, current ordinary snapshot-specific reads are `S0 + S1` and can retain both maps simultaneously. This option still reads `S0 + S1` but retains only `S0` plus a bounded post-read block and path metadata. Input parsing and output semantic/hash reads remain additional passes. It can reduce peak Python payload residency; it **does not** make memory bounded independently of `S0`, solve large baseline admission, or establish Python bounded typed-space support. It cannot by itself explain or meet the R Xenopus performance budget.

Before code, compare old and proposed changed-path sets using exact-byte oracle fixtures: unchanged, newly created, replaced, truncated, lengthened, deleted and nested files; symlinks/FIFOs; empty directories and path-set closure; late output tamper; handler exception, invalid receipt and rollback. Verify original error codes and unchanged output/receipt bytes. For 64/256 MiB inert stages, propose a pre-code target of at most two snapshot-specific full reads, 1 MiB post-read blocks, peak payload RSS no greater than `S0 + 16 MiB` plus separately measured path/index and parsed-object memory, and no more than 1.10x ordinary success elapsed. Measure process-isolated warm-cache and first-touch trials separately; report failures and retain the old path if the target misses. These are prospective thresholds, not measured gains.

An anonymous `TemporaryFile` backup is **not** selected as a shortcut. The local Python 3.11 POSIX `tempfile.py:727-796` uses `O_TMPFILE` when available but falls back to create-then-unlink, leaving a hard-kill window before unlink; non-POSIX aliases `TemporaryFile` to a named temporary file. A strict unnamed-file implementation would be platform/filesystem-specific and still needs parent/child liveness and disk-pressure proof. Compression of `before` bytes has no worst-case memory bound. The existing disk-backed plan remains STOP until R-owned scratch lifecycle proof.
