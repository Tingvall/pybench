## 1. Ordinary stage snapshot first

### Actual path

`src/pybench/protocol_v3.py:_snapshot()` (lines 695-703) reads every staged file into a `dict[str, bytes]`. `execute_operation_pack_v3()` calls it before and after the handler (lines 1447, 1555), and `_restore()` replays the in-memory bytes on failure (lines 714-723). `src/pybench/protocol_v4.py:execute_operation_pack_v4()` repeats this for ordinary process-v4 calls (lines 3294-3306, 3530-3540). The ABI4/process-v5 graph path already uses `protocol_v5.py:DiskStageSnapshot` (lines 80-160): bounded 1 MiB copy-plus-hash before execution and independent post-handler hashing, with a private disk backup for rollback. The existing graph measurement for a 64 MiB one-file baseline was 0.126628 -> 0.067856 seconds and +456 KiB process RSS, but that is **not** an ordinary v3/v4 measurement.

Let `S0` and `S1` be pre/post staged file bytes, `I` projected input JSON bytes, and `O` staged output JSON bytes. The ordinary path currently reads at least `S0 + I + S1` from staged files; output validation adds one `O` JSON read and a separate output-file hash read (plus registry/provenance reads). It retains byte copies for both snapshots, so peak stage-payload residency can include `S0 + S1`, before parsed input/output objects. The stage-tree walks are separate metadata passes. These are logical read counts, not measured physical disk IO.

### Proposed candidate and pre-code gate

In a later implementation branch, evaluate a narrow disk-backed baseline for ordinary v3/v4 calls; direct reuse of `DiskStageSnapshot` is **not** cleared. Its graph caller constructs the helper before `_tree`, active-pack and consumed-capability checks, while the `finally` begins later (`protocol_v4.py:3294-3320`). The ordinary candidate must establish ownership immediately after successful construction: an outer `try/finally` or context manager covers tree walk, activation, capability checks, input reads, handler, audit, receipt validation and every fault hook. Constructor partial-copy failure must remove its backup. Successful and failing exits must close it, including failures before handler entry. Do not alter ABI4 defaults or graph behavior silently.

The baseline and post-handler scan must independently hash **actual** staged bytes using bounded 1 MiB blocks. Under the existing SHA-256 content-identity trust model, comparing actual `(size, sha256)` fingerprints instead of the old byte maps is an explicit representation change, not byte equality. Keep byte maps as test oracles, preserve the separate `_tree` path inventory, changed-file closure, output semantic validation, mutation manifest, receipts, and R-side independent audit/rollback. Never infer output semantic equality from file hashes, size/mtime, or a handler-supplied receipt. Existing transient changes restored before final audit remain outside the approved detection claim.

### Backup ownership and abnormal termination

The current graph helper creates its backup with `mkdtemp` outside the stage (`protocol_v5.py:134-160`). Python `finally` cannot run after `os._exit`, SIGKILL or timeout termination. Before implementation, identify and prove an **existing R-owned private transition parent** that can own and remove a backup after child death. The backup location must be derivable and containable by that parent without a new wire field, durable service, or receipt trust. If the existing R lifecycle cannot provide this, do not select disk backing for ordinary paths. Parent cleanup must inventory both the stage and backup root before/after, reject backup residue, and preserve the independent R transaction/stage rollback. Do not promise standalone dead-Python self-restoration.

Add actual mutation-before-hard-exit and timeout cases (the current hard-exit test around `tests/test_operation_pack_v2.py:1508-1550` does not establish this), plus interrupted-baseline construction. A killed child may leave a private backup until the existing parent cleanup runs; it must leave no durable source/recipient mutation and no backup after that cleanup. Explicitly record who removes the stage and backup when Python cannot run.

### Root, metadata, diagnostics and cleanup

Capture the owned stage-root directory identity/type at baseline. At audit and rollback, recheck with non-following path operations. A missing root, replacement file, or root symlink must fail closed; never enumerate or delete through a changed root or touch an outside sentinel. Restore only through a verified owned root. If the original root is gone, raise an explicit recovery failure for the R parent to clean rather than claiming Python can safely recreate an unowned path. Reject nested symlink/special-object substitutions before traversal. This is an owned-stage rule, not a general Python sandbox guarantee.

For the ordinary candidate, require exact file bytes and path closure **plus** preservation of file mode bits and empty directories for both top-level and nested entries; define and test these under an explicit umask. The old byte-map restore does not guarantee modes/empty directories, and `DiskStageSnapshot.restore()` uses `copyfile` for top-level files, so existing graph tests do not establish this policy. Do not silently replace `_tree` checks with files-only fingerprints. State that ACLs/xattrs and platform-specific metadata are outside this candidate unless separately approved.

A neutral private helper or lazy ordinary adapter must preserve established ordinary error code/phase (`PYBENCH_OUT_OF_SCOPE_MUTATION`/audit for symlink mutation) and avoid the `protocol_v5` -> v4/v3 import cycle. Graph defaults and graph error codes stay unchanged. Earlier rejection of FIFO/unsupported entries is a reviewed admission refinement, with its exact ordinary diagnostic tested rather than inherited accidentally from graph `_fail` (`PYBENCH_GRAPH_CAPABILITY_MISMATCH`/execution).

On an error, attempt writer consumption, safe restore and backup close in nested `finally` blocks so one cleanup error does not skip the rest. Preserve the original handler/audit exception and surface every secondary restore/close failure in existing supervised logs and numeric command/transition status evidence, without adding a wire field or success receipt. The independent R owner must reject and clear its transaction/stage. Test read, write, copy, restore and cleanup faults, including faults before the handler.

The expected snapshot-specific success-path staged-source reads remain **two complete passes**, not one: copy-plus-hash `S0`, then independent hash `S1`. Input parsing, output semantic parse/hash and registry/provenance reads are additional executor work, measured separately. Disk backing writes `S0` to private scratch; rollback reads/writes up to `S0`. The admissible advantage is bounded Python payload residency, not reduced authentication. Pre-code targets for 64 MiB and 256 MiB inert staged-file and nested multi-file fixtures: at most two stage-content reads on success, one backup write, bounded 1 MiB chunks, and payload-attributable peak RSS growth from a 1 MiB control at most 16 MiB **plus separately reported file-count/path-index metadata**. Keep parsed inputs/outputs out of this snapshot-specific RSS probe; measure them in lifecycle tests. Median success elapsed must be no worse than 1.10x the current ordinary path and median failure/rollback no worse than 1.20x; otherwise retain current behavior and report the miss.

Before code, fix trial order, warmup, fixture sizes, elapsed/RSS scope and failure injection. Run five fresh-process warm-cache trials and five fresh-process **first-touch** trials with unique fixture bytes, reporting that first-touch is not guaranteed cold physical media: no privileged global cache flush. Record logical source/backup bytes, allocated disk blocks, observed physical IO where available, backup/free-space pressure, peak RSS, stage file count and file-system type. Neither the 16 MiB payload allowance nor an R graph quota is a process-wide memory/disk cap. Snapshot-only measurements are necessary but not sufficient; ordinary end-to-end mutation/audit/receipt/rollback tests retain every authority. These targets are prospective, not observed ordinary-path gains or an explanation of the R Xenopus miss.

Focused tests before any selection: existing `tests/test_operation_pack_v2.py` fault/interrupt and independent-audit cases around lines 1193-1307, v3/v4 successor staged mutation and receipt cases, and `tests/test_protocol_v5_graph_sdk.py` snapshot restore and nested symlink/FIFO cleanup cases around lines 139-190. Add ordinary v3/v4 cases for created/replaced/deleted/nested files; missing, forged, incomplete, self-rehashed and mismatched receipts; late post-writer and undeclared sibling mutation; input mutation between baseline and read; inactive pack, consumed capability and tree-walk failure before handler; mutation-before-hard-exit/timeout; interrupted baseline; missing/file/symlink root and outside sentinel; nested symlink; explicit umask with top-level/nested modes and empty directories; and secondary restore/close faults. Verify exact pre/post byte maps, directory/path/mode policy and no stage/backup residue after owner cleanup. Preserve accepted current behavior for a transient change restored before final audit; do not claim to detect it.

## Deferred 2. Output JSON reread/serialization

This design is **not approved for implementation** by Sable's priority-1 review. It is retained only as a later investigation inventory.

Both `protocol_v3.py` (lines 1523-1555) and `protocol_v4.py` (lines 3480-3535) reread each staged `payload.json`, parse it, canonicalize both parsed and writer-held objects for semantic comparison, then reread/hash output paths. The independent stage post-snapshot reads those files again. This is extra serialization and multiple reads, but the parsed semantic comparison is a security check and currently permits noncanonical whitespace/key order when values are unchanged.

Before proposing code, instrument actual output sizes and count canonical encodings/reads for tiny, 64 MiB and multi-output fixtures. A candidate may retain the canonical writer encoding for comparison only if memory growth stays within an explicit bound and current semantic acceptance is unchanged. A direct raw-byte equality check would narrow accepted formatting behavior and is **not** approved here; hash-only equality would replace exact semantic comparison and is also not approved. Never remove the independent post-handler stage scan or the mutation manifest. Pre-code target: at most one canonicalization of the writer-held value across writing **and** audit, one canonicalization of the independently parsed staged value, and one independent audit pass; no more than 1.10x current peak RSS or elapsed on tiny outputs, with a measured improvement on large outputs. Test reordered keys/whitespace accepted as today, changed value rejected, malformed JSON rejected, self-rehashed receipt rejected, and rollback with zero residue.

## Deferred 3. Public space getter selection

This design is **not approved for implementation** by Sable's priority-1 review. It is retained only as a later investigation inventory.

`src/pybench/getters.py:space()` (lines 389-455) loads all HDF5 coordinates for selected dimensions before selecting requested rows (lines 420-428); the wide `space_2d` SQL branch reads every row before filtering/reordering requested cells (lines 433-455). These are public getter costs, not a Python ABI typed-space capability. Keep axis ordering, duplicate request behavior, missing-cell diagnostics, dimension validation, return type and full-selection behavior unchanged. A future bounded row-selection design must account for h5py sorted/unique fancy-index constraints and reconstruct caller order; the SQL path must use bounded parameter batches and preserve cell-row order. Do not introduce a new storage format, getter API, or schema.

Pre-code target for 1% selected cells from a 256 MiB coordinate payload: coordinate bytes read and resident coordinate values proportional to selected rows plus a bounded block allowance (at most 16 MiB), while full selection is no worse than 1.10x current elapsed/RSS. The existing full `cell_ids` axis read may still scale with total cells; measure and disclose it rather than claiming a fully bounded getter. Include empty/full/reordered/duplicate/missing selections, repeated dimensions, UTF-8 IDs, HDF5 and wide-SQL storage, and exact value/ordering parity. This is a separate change after stages 1-2 are reviewed.
